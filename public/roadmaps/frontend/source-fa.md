# رودمپ ماژولار فرانت‌اند

### مسیری قابل‌شخصی‌سازی برای یادگیری و ارزیابی مهارت‌های فرانت‌اند

این رودمپ برای این طراحی شده که هر فرد بتواند بر اساس مهارت‌های فعلی‌اش
مسیر مناسب خودش را پیدا کند؛ نه اینکه همه مجبور باشند یک مسیر ثابت و
یکسان را از ابتدا تا انتها طی کنند.

ساختار آن از مهارت‌های اصلی فرانت‌اند الهام گرفته و با توجه به نیازهای
توسعه محصول در سال ۲۰۲۶ تنظیم شده است. منابع مرجع در پایان آمده‌اند.

## این رودمپ چطور کار می‌کند؟

مسیر از چند **ماژول مستقل** تشکیل شده است. هر ماژول هدف، موضوعات اصلی،
تمرین و معیار مشخصی برای سنجش یادگیری دارد.

-   **از جایی شروع کن که لازم داری:** معیار پایان هر ماژول را بررسی کن.
    اگر می‌توانی آن را به‌تنهایی انجام بدهی، از آن عبور کن؛ اگر نه، همان‌جا
    نقطه شروع توست.
-   **موضوعات اصلی را از موضوعات تکمیلی جدا کن:** ابتدا بخش «هسته» را
    یاد بگیر. بخش «تعمیق» برای زمانی است که پروژه یا شغل تو به دانش
    بیشتری نیاز دارد.
-   **لازم نیست همه ماژول‌ها را به یک ترتیب ثابت طی کنی:** بعضی از آن‌ها
    را می‌توان هم‌زمان پیش برد و بعضی را، در صورت تسلط، کنار گذاشت.
-   **پیشرفت را با توانایی انجام کار بسنج، نه تعداد ویدئوها یا ساعت
    مطالعه.**

### چند اصطلاح که در این مسیر می‌بینی

-   **هسته:** حداقل دانشی که برای کار عملی در آن موضوع لازم است.
-   **تعمیق:** مباحث پیشرفته‌تر و اختیاری که بسته به نیاز می‌توانی سراغشان
    بروی.
-   **پیش‌نیاز:** مهارتی که بهتر است پیش از شروع یک ماژول بلد باشی.
-   **معیار پایان:** کاری مشخص که نشان می‌دهد موضوع را فهمیده‌ای و می‌توانی
    از آن استفاده کنی.
-   **AI:** ابزارهای هوش مصنوعی که می‌توانند در یادگیری، نوشتن پیش‌نویس و
    بررسی کد کمک کنند؛ اما جای درک و تصمیم‌گیری تو را نمی‌گیرند.

## پیش از شروع: پایه‌های وب

این بخش یک ماژول اجباری با شماره نیست؛ مفاهیم پایه‌ای است که درک بقیه
مسیر را آسان‌تر می‌کند. هدف، فهمیدن سازوکار وب است، نه حفظ کردن تعریف‌ها.

**موضوعات اصلی** - اینترنت و ارتباط کلاینت و سرور؛ IP، DNS و CDN - HTTP
و HTTPS؛ متدها، کدهای وضعیت، هدرها، کوکی، CORS و مفهوم TLS - مسیر یک
درخواست: از وارد کردن URL تا نمایش صفحه در مرورگر - مرورگر و رندر صفحه؛
DOM، CSSOM، reflow و repaint - API و JSON؛ تفاوت کلی CSR، SSR و SSG -
دامنه، میزبانی وب، ترمینال و package manager

**معیار پایان:** بتوانی با زبان خودت توضیح بدهی وقتی یک URL را وارد
می‌کنی، چه اتفاقی می‌افتد تا صفحه نمایش داده شود.

## ماژول ۱: HTML و CSS

**هدف:** ساخت صفحه‌های درست، قابل‌دسترس و واکنش‌گرا؛ و درک CSS به‌اندازه‌ای
که بتوانی کد تولیدشده توسط هوش مصنوعی را ارزیابی و اصلاح کنی.

**پیش‌نیاز:** پایه‌های وب.

**موضوعات اصلی** - ساختار HTML: عنوان‌ها، بخش‌بندی معنایی، فهرست‌ها،
لینک‌ها، دکمه‌ها، ورودی‌ها و فرم‌ها - انتخاب عناصر HTML بومی و مناسب به‌جای
ساخت اجزای سفارشیِ غیرضروری - مبانی CSS: مدل جعبه‌ای، cascade و
specificity - ساخت چیدمان با Flexbox، Grid و positioning - طراحی
واکنش‌گرا با media query - دسترس‌پذیری پایه: HTML معنایی، label مناسب و
کنتراست رنگ

**برای تعمیق بیشتر، در صورت نیاز** - container query، متغیرهای CSS،
stacking، overflow و containment

**تمرین پیشنهادی:** یک صفحه قیمت‌گذاری یا تنظیمات بساز که در موبایل و
دسکتاپ به‌درستی نمایش داده شود.

**نقش هوش مصنوعی:** از آن برای توضیح مفاهیم و راهنمایی استفاده کن؛ تلاش
کن خودت کد را بنویسی و بفهمی.

**معیار پایان:** بتوانی بدون کمک هوش مصنوعی، با استفاده از DevTools یک
مشکل چیدمان را پیدا و برطرف کنی.

## ماژول ۲: ابزارهای توسعه

این ماژول را می‌توان از همان ابتدای مسیر و هم‌زمان با HTML، CSS و
JavaScript یاد گرفت.

**هدف:** توانایی کار روی یک پروژه واقعی، بررسی خطاها و استفاده از
ابزارهای استاندارد توسعه.

**موضوعات اصلی** - Git و GitHub: commit، branch، merge، pull request و
حل تعارض‌ها (conflict) - ابزارهای مرورگر (DevTools): بخش‌های Elements،
Network، Console، Performance و Application - اشکال‌زدایی (debugging):
خواندن stack trace و پیدا کردن علت خطا به‌صورت مرحله‌ای - npm و ابزارهای
ساخت پروژه، مانند Vite

**معیار پایان:** بتوانی با branch و pull request روی یک پروژه کار کنی و
یک مشکل مربوط به درخواست شبکه را از بخش Network پیدا کنی.

## ماژول ۳: JavaScript

**هدف:** ساخت پایه‌ای محکم برای فهم رفتار برنامه‌ها و کار با فریم‌ورک‌ها.
این بخش از مهم‌ترین سرمایه‌گذاری‌های مسیر است؛ چون استفاده از ابزارهای هوش
مصنوعی بدون درک JavaScript می‌تواند به کپی‌کردن کدی منجر شود که اشکال‌زدایی
و توسعه‌اش دشوار است.

**پیش‌نیاز:** آشنایی اولیه با HTML از ماژول ۱.

**موضوعات اصلی** - مقدارها، نوع داده‌ها، scope، closure و ماژول‌ها -
آرایه‌ها و آبجکت‌ها و تبدیل‌های رایج آن‌ها؛ map و set - رویدادها (events)،
event delegation و به‌روزرسانی DOM - Promise، async/await، timer، fetch و
مدیریت خطا - ذخیره‌سازی در مرورگر (browser storage)

**برای تعمیق بیشتر، در صورت نیاز** - `this`، prototype، iterator،
generator و event loop در سطح عمیق‌تر

**تمرین‌های پیشنهادی** - فرم چندمرحله‌ای با اعتبارسنجی - جدول دارای جست‌وجو
و مرتب‌سازی - داشبورد کوچکی که داده را از API دریافت کند - صفحه قیمت‌گذاری
یا تنظیمات

این پروژه‌ها کمک می‌کنند بفهمی فریم‌ورک‌ها چه مسائلی را حل می‌کنند.

**نقش هوش مصنوعی:** از آن بخواه خطاها را توضیح دهد یا راهنمایی‌ات کند؛
اصلاح کد را خودت انجام بده.

**تست:** در این مرحله تست‌نویسی گسترده لازم نیست. در صورت تمایل، چند تست
ساده برای توابع خالص بنویس.

**معیار پایان:** بتوانی بدون هوش مصنوعی یک برنامه کوچک بسازی که از API
داده بگیرد، و توضیح بدهی چرا ممکن است برای توسعه آن به فریم‌ورک نیاز
داشته باشی.

## ماژول ۴: TypeScript

**هدف:** تعریف نوع داده‌ها و مشخص کردن مرزهای سیستم، تا بخشی از خطاها پیش
از اجرای برنامه شناسایی شوند.

**پیش‌نیاز:** ماژول ۳، JavaScript.

**موضوعات اصلی** - نوع‌های پایه، union، `interface` و `type`، و
genericهای ساده - تعریف نوع برای props کامپوننت‌ها و پاسخ API - narrowing
و استفاده از `unknown` به‌جای `any` در موقعیت‌های مناسب - خواندن و رفع
خطاهای TypeScript - استفاده از Zod برای اعتبارسنجی داده در مرزهای سیستم

**برای تعمیق بیشتر، در صورت نیاز** - utility typeهای پیشرفته و
conditional typeها؛ این موارد برای همه پروژه‌های معمول ضروری نیستند.

**معیار پایان:** بتوانی پاسخ یک API را تایپ کنی، داده‌های ناقص را با Zod
مدیریت کنی و از `any` غیرضروری پرهیز کنی.

**ترکیب پیشنهادی:** می‌توانی این ماژول را هم‌زمان با ماژول React یاد
بگیری.

## ماژول ۵: React

**هدف:** فهمیدن اینکه رابط کاربری چگونه با تغییر داده‌ها به‌روزرسانی می‌شود
و داده و وضعیت برنامه چگونه بین کامپوننت‌ها جریان پیدا می‌کند.

**پیش‌نیاز:** ماژول ۳، JavaScript.

**موضوعات اصلی** - کامپوننت‌ها و props، state و rendering - effects و
محدودیت‌های استفاده از آن‌ها - فرم‌های controlled، فهرست‌ها و key - context
و ref - composition و error boundary - الگوهای دریافت داده (data
fetching)

**برای تعمیق بیشتر، در صورت نیاز** - الگوهای پیشرفته composition،
بهینه‌سازی render و کامپوننت‌های headless سفارشی

**تست‌نویسی:** از این ماژول تست کامپوننت را جدی‌تر شروع کن. می‌توانی از
Vitest و Testing Library استفاده کنی و روی رفتار قابل‌مشاهده کاربر تمرکز
داشته باشی، نه جزئیات داخلی پیاده‌سازی. تست‌ها به شناسایی باگ‌ها و بررسی کد
تولیدشده با هوش مصنوعی کمک می‌کنند.

**نقش هوش مصنوعی:** از آن پیش‌نویس بخواه، سپس راه‌حل‌ها را با هم مقایسه کن
و مزایا و محدودیت‌های هرکدام را بسنج.

**معیار پایان:** بتوانی توضیح بدهی هر state بهتر است در کدام بخش قرار
بگیرد: کامپوننت، context، URL یا لایه دریافت داده.

------------------------------------------------------------------------

## ماژول ۶: ساخت اپلیکیشن واقعی

**هدف:** کنار هم قرار دادن کامپوننت‌ها، داده، API، فرم‌ها و وضعیت‌های رابط
کاربری برای ساخت یک محصول قابل‌استفاده.

**پیش‌نیاز:** ماژول‌های ۴ و ۵.

**موضوعات اصلی**

**۱. داده و API** - مصرف REST API؛ کدهای وضعیت، هدرها، caching و
pagination - ساخت service layer - استفاده از Axios یا fetch و TanStack
Query - تفاوت server state و client state؛ برای نمونه، استفاده از
Zustand برای state سمت کلاینت در صورت نیاز

**۲. مسیریابی و احراز هویت** - routing و مدیریت وضعیت‌های احراز هویت -
مفاهیم JWT، OTP و refresh token - مدیریت مجوزها (permissions)

**۳. فرم‌ها** - React Hook Form و Zod - نمایش خطای هر فیلد و مدیریت
submit غیرهم‌زمان - مدیریت شکست درخواست و امکان بازیابی

**۴. وضعیت‌های رابط کاربری** - طراحی حالت‌های loading، empty، error و
disabled - بررسی رفتار صفحه در موبایل - پیاده‌سازی optimistic update،
pagination و جست‌وجو

**۵. ساخت رابط کاربری** - Tailwind، shadcn و Radix - حالت تاریک (dark
mode) - انیمیشن‌های کوچک و هدفمند (microinteraction)

**برای تعمیق بیشتر، در صورت نیاز** - ارتباط بلادرنگ با WebSocket یا SSE،
آپلود فایل و ثبت رویدادهای تحلیلی (analytics events)

**تست‌نویسی:** از MSW برای شبیه‌سازی API در تست‌ها استفاده کن و جریان‌های
اصلی فرم را آزمایش کن.

**نقش هوش مصنوعی:** از آن برای تهیه پیش‌نویس، پیشنهاد edge caseها و نوشتن
تست کمک بگیر؛ سپس بررسی کن که تست‌ها واقعاً رفتارهای مهم را پوشش می‌دهند.

**تمرین پیشنهادی:** سه پروژه از سه نوع بساز: - داشبورد داده‌محور -
اپلیکیشن فرم‌محور - یک جریان کاری محصول (product workflow)

برای هر پروژه یادداشت کوتاهی ثبت کن: مسئله چه بود، چه تصمیم‌هایی گرفتی،
چه حالت‌های خاصی را در نظر گرفتی، چطور تست کردی و در آینده چه چیزی را
بهتر می‌کنی.

**معیار پایان:** بتوانی یک نیازمندی مبهم را به رابط کاربری قابل‌استفاده
تبدیل کنی، بدون اینکه برای تصمیم‌گیری در هر قدم به راه‌حل آماده نیاز داشته
باشی.

## ماژول ۷: Next.js و انتشار محصول

**هدف:** آماده‌سازی اپلیکیشن برای استفاده واقعی؛ با توجه به سرعت، قابلیت
پیدا شدن در موتورهای جست‌وجو و امنیت پایه.

**پیش‌نیاز:** ماژول ۶.

**موضوعات اصلی** - App Router و تفاوت Server Components و Client
Components - SSR، SSG، ISR و caching - SEO و metadata - کارایی وب: Core
Web Vitals، code splitting و بهینه‌سازی تصاویر - اندازه‌گیری عملکرد پیش و
پس از بهینه‌سازی - امنیت پایه: XSS، نگهداری توکن، مفهوم CSRF و ریسک
وابستگی‌های نرم‌افزاری - انتشار (deploy) و CI ساده، شامل اجرای lint و test

**تست‌نویسی:** با Playwright برای مسیرهای حیاتی تست end-to-end (E2E)
بنویس.

**نقش هوش مصنوعی:** می‌توانی از ابزارهایی مانند Cursor یا Claude Code در
یک روند spec-driven استفاده کنی: کار را به تسک‌های کوچک و قابل‌آزمایش
تقسیم کن، قوانین پروژه را مشخص کن و تصمیم‌های معماری را آگاهانه بگیر.

**معیار پایان:** یکی از پروژه‌های ماژول ۶ را با Next.js پیاده‌سازی و منتشر
کرده باشی و نتایج Lighthouse را پیش و پس از بهینه‌سازی مقایسه کنی.

## ماژول ۸: انتخاب مسیر تخصصی (اختیاری)

بعد از اینکه توانستی یک رابط کاربری محصولی بسازی و آن را منتشر کنی،
می‌توانی یک یا دو حوزه را بر اساس علاقه و نیاز کاری انتخاب کنی. لازم نیست
از ابتدای مسیر سراغ این موارد بروی.

-   Design System
-   بهینه‌سازی عملکرد وب (Web Performance)
-   توسعه فول‌استک محصول‌محور، برای ساخت MVP مستقل
-   رابط کاربری محصولات هوش مصنوعی، مانند streaming و agent UI
-   React Native
-   بین‌المللی‌سازی، امنیت و حریم خصوصی در فرانت‌اند

### چطور از هوش مصنوعی درست استفاده کنیم؟

هوش مصنوعی می‌تواند سرعت توسعه را بالا ببرد، اما نباید جای یادگیری را
بگیرد. اگر پروژه‌ها را صرفاً با کپی کردن کد تمام کنی، ممکن است هنگام
مصاحبه، بازبینی کد یا رفع خطا نتوانی از تصمیم‌هایت دفاع کنی.

هنگام بازبینی کد تولیدشده با هوش مصنوعی، این موارد را بررسی کن:

-   آیا با صفحه‌کلید می‌توان با رابط کاربری کار کرد؟
-   آیا حالت‌های loading، empty و error درست مدیریت شده‌اند؟
-   آیا چیدمان در صفحه‌های باریک به هم می‌ریزد؟
-   اگر API خطا بدهد، رفتار برنامه قابل‌قبول است؟
-   آیا `any` غیرضروری یا وابستگی اضافه وارد پروژه شده است؟

## چطور این رودمپ را برای خودت تنظیم کنی؟

### ۱. نقطه شروع را با معیار پایان مشخص کن

از پایه‌های وب و ماژول ۱ شروع به ارزیابی کن. هرجا نتوانستی معیار پایان را
بدون کمک انجام بدهی، همان‌جا نقطه شروع مناسب توست. اگر معیار را به‌راحتی
انجام می‌دهی، می‌توانی از آن بخش عبور کنی.

### ۲. از وضعیت فعلی خودت شروع کن

  -----------------------------------------------------------------------
  وضعیت فعلی                          نقطه شروع پیشنهادی
  ----------------------------------- -----------------------------------
  تازه‌کار و بدون تجربه برنامه‌نویسی    پایه‌های وب، سپس ماژول ۱

  برنامه‌نویسی بلدی اما با وب آشنا     ماژول‌های ۱ و ۲
  نیستی                               

  با وب و JavaScript آشنایی داری      ماژول ۴ یا ۵، با توجه به شکاف‌های
                                      دانشت

  با React کار کرده‌ای و اپلیکیشن      ماژول ۶؛ همراه با بررسی تست‌نویسی و
  ساخته‌ای                             دسترس‌پذیری

  فرانت‌اندکار حرفه‌ای هستی             ماژول‌های ۷ و ۸ و بازبینی مهارت‌های
                                      عرضی
  -----------------------------------------------------------------------

این جدول نقطه شروع پیشنهادی است، نه قانون قطعی. معیارهای پایان هر ماژول
تصمیم دقیق‌تری به تو می‌دهند.

### ۳. تعداد ماژول‌ها را تغییر بده

-   **ادغام:** ماژول‌های TypeScript و React را می‌توان هم‌زمان پیش برد.
    JavaScript را نیز می‌توان با پروژه‌های بدون فریم‌ورک همراه کرد.
-   **حذف:** اگر معیار پایان ماژولی را از قبل داری، لازم نیست آن را
    دوباره از ابتدا یاد بگیری. اگر Next.js برای نوع پروژه‌ات لازم نیست،
    بخش مربوط به آن را سبک‌تر کن؛ اما انتشار و تست را نادیده نگیر.
-   **اضافه کردن:** اگر به مهارت تازه‌ای نیاز داری، آن را به شکل یک ماژول
    تعریف کن: هدف، پیش‌نیاز، موضوعات اصلی، تمرین و معیار پایان. برای
    مثال، می‌توانی ماژولی برای Vue یا مبانی بک‌اند اضافه کنی.

### ۴. عمق یادگیری را متناسب با نیازت انتخاب کن

موضوعات «هسته» حداقل لازم برای کار عملی را مشخص می‌کنند. سراغ بخش «تعمیق»
برو وقتی که پروژه، شغل یا هدف مشخصی به آن نیاز دارد. لازم نیست همه
موضوعات پیشرفته را از ابتدا یاد بگیری.

## برای بازبینی این نسخه

برای اینکه نسخه نهایی هم برای مطالعه مستقل مناسب باشد و هم بعداً روی
وب‌سایت قرار بگیرد، لطفاً هنگام بررسی به این پرسش‌ها توجه کن:

1.  آیا توضیح ساختار ماژولار و نحوه انتخاب نقطه شروع روشن است؟
2.  آیا ترتیب موضوعات و پیش‌نیازها منطقی به نظر می‌رسد؟
3.  آیا بخش‌های هر ماژول بیش از حد فنی، طولانی یا مبهم‌اند؟
4.  آیا معیارهای پایان، توانایی عملی را به‌اندازه کافی می‌سنجند؟
5.  آیا موضوع مهمی جا افتاده یا موضوعی هست که بهتر باشد اختیاری شود؟
6.  اگر قرار باشد این رودمپ در وب‌سایت تعاملی شود، کدام بخش‌ها باید به شکل
    ماژول، چک‌لیست، تمرین یا توضیح تکمیلی نمایش داده شوند؟
